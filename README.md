# Генератор договоров B2B

Настольное приложение для Windows: формирует договор в формате `.docx` из
шаблона Word и карточки компании в Excel. Рассчитано на сотрудника без
технической подготовки.

## Назначение

1. Выбрать шаблон договора (`.docx`).
2. Выбрать карточку компании (`.xlsx`).
3. Проверить и при необходимости исправить извлечённые реквизиты прямо в окне.
4. Ввести номер договора или сформировать его автоматически.
5. Проверить данные — программа сообщает об ошибках и предупреждениях.
6. Сформировать новый документ, не изменяя исходные файлы.
7. Получить отчёт о заменах, пустых значениях и незаполненных плейсхолдерах.

## Конфиденциальность

Все данные обрабатываются **только на этом компьютере**. Приложение не
обращается к сети, не использует облачные сервисы, внешние API и телеметрию.
Реестр договоров и настройки хранятся локально; полные карточки компаний в
реестр и журнал не записываются, ИНН в журнале маскируется.

## Поддерживаемые форматы

| Что | Формат |
|-----|--------|
| Шаблон договора | `.docx` (Word 2007 и новее) |
| Карточка компании | `.xlsx` |
| Результат | `.docx` |

Формат `.xls` **не поддерживается**: сохраните карточку как «Книга Excel
(*.xlsx)». Файлы `.doc` также не поддерживаются.

## Как работает чтение карточки

Читаются все **видимые** листы книги. В первых четырёх колонках каждой строки
ищется метка поля; значением берётся первая непустая ячейка справа (в пределах
шести колонок). Первое найденное значение поля используется; если то же поле
встречается ещё раз с другим значением, показывается предупреждение о дубликате.

Метки сравниваются без учёта регистра, лишних пробелов, завершающих двоеточий
и различия `ё`/`е`. Поддерживаются синонимы: например, `ИНН`, `ИНН организации`,
`ИНН заказчика`; `Тел`, `Тел.`, `Телефон`; `e-mail`, `email`,
`Электронная почта`. Полный список — в `contract_generator/fields.py`
(единственное место, где описаны поля).

Идентификаторы (ИНН, КПП, ОГРН, БИК, счета) всегда сохраняются как строки:
экспоненциальная запись исключена, ведущие нули восстанавливаются по числовому
формату ячейки. Даты читаются как из настоящих ячеек-дат Excel, так и из строк
`дд.мм.гггг`, `дд/мм/гггг`, `дд-мм-гггг`, `гггг-мм-дд`.

## Плейсхолдеры шаблона

В шаблоне пишите `{имя_поля}`. Плейсхолдер может быть разбит Word на несколько
фрагментов — программа это учитывает и сохраняет форматирование окружающего
текста (жирность, курсив, подчёркивание, шрифт, размер, цвет, гиперссылки).
Обрабатываются: основной текст, таблицы, вложенные таблицы, верхние и нижние
колонтитулы (включая колонтитулы первой и чётных страниц).

### Реквизиты

| Плейсхолдер | Значение |
|-------------|----------|
| `{company_name}` | Наименование как в карточке |
| `{company_name_full}` | «Общество с ограниченной ответственностью «Ромашка»» |
| `{company_name_short}` | «Ромашка» (без ОПФ и кавычек) |
| `{ownership_form}` | ООО, АО, ИП … |
| `{ownership_full}` | Полное наименование ОПФ |
| `{ownership_form_genitive}` и другие падежи | Аббревиатуры ОПФ не склоняются, возвращается исходное значение |
| `{inn}`, `{kpp}`, `{ogrn}` | Идентификаторы |
| `{legal_address}`, `{postal_address}` | Адреса |
| `{bank_name}`, `{bik}`, `{bank_account}`, `{corr_account}` | Банковские реквизиты |
| `{phone}`, `{email}`, `{domains}` | Контакты |
| `{edo_provider}` | Оператор ЭДО |

### Подписант

| Плейсхолдер | Значение |
|-------------|----------|
| `{signatory_full}` | ФИО полностью |
| `{signatory_short}` | ФИО кратко |
| `{signatory_position}` | Должность (именительный падеж) |
| `{signatory_position_genitive}` | Родительный: «Генерального директора» |
| `{signatory_position_dative}`, `_accusative}`, `_instrumental}`, `_prepositional}` | Остальные падежи |
| `{signatory_gender}` | «мужской» / «женский» |
| `{based_on}` | «Устава», «Доверенности № …» |
| `{acting_form}` | «действующего» / «действующей» |
| `{acting_form_full}` | «действующего на основании Устава» |
| `{based_on_agreed}` | «действующего на основании» |
| `{based_on_agreed_full}` | То же, что `{acting_form_full}` |

### Договор

| Плейсхолдер | Значение |
|-------------|----------|
| `{contract_number}` | Номер договора |
| `{contract_date}` | «01» марта 2025 г. |
| `{contract_date_numeric}` | 01.03.2025 |
| `{contract_end_date}`, `{contract_end_date_numeric}` | Дата окончания |
| `{contract_term_years}` | Срок действия, лет |

Все плейсхолдеры прежней версии продолжают работать. Незнакомые выражения
`{...}` программа не трогает, но перечисляет их в отчёте как «неизвестные
плейсхолдеры».

## Проверка данных

Проверка выполняется до генерации и разделяет замечания на два вида:

* **Ошибки** — генерация заблокирована (кнопка неактивна). Например: пустое
  обязательное поле, ИНН, не проходящий проверку контрольного разряда,
  БИК не из 9 цифр, счёт, не согласующийся с БИК, нераспознанная дата
  договора, дата окончания не позже даты заключения.
* **Предупреждения** — генерация возможна после явного подтверждения.
  Например: ОГРН с неверной контрольной цифрой, КПП у ИП, автоматически
  определённый пол подписанта, должность вне справочника, дубликат поля
  в карточке, сомнительный адрес почты.

Проверяются контрольные разряды ИНН (10 и 12 знаков), ОГРН/ОГРНИП и
контрольный ключ расчётного и корреспондентского счетов относительно БИК.
Программа **не исправляет** юридические и банковские данные молча — она
только сообщает о проблеме.

Набор обязательных полей зависит от шаблона: если шаблон не использует
банковские плейсхолдеры, банковские реквизиты не требуются.

## Пол подписанта и должности

* Явно указанный в карточке пол (`Пол подписанта`) считается достоверным.
* Если пол не указан, он определяется **только по отчеству** (`-ович/-евич`,
  `-овна/-евна`), а не по первому слову ФИО. Определённое таким образом
  значение помечается в таблице статусом `АВТО` и сопровождается
  предупреждением.
* Если отчество не распознано, принимается мужской род и выдаётся
  предупреждение.
* Известные должности склоняются по справочнику. Неизвестные **не склоняются**:
  исходное значение сохраняется во всех падежах, выдаётся предупреждение.
  Падежные формы можно исправить вручную прямо в таблице.

## Номер договора

Номер можно ввести вручную или сформировать кнопкой «Сформировать номер».
Формат настраивается (поле `number_format` в настройках), по умолчанию —
`СЛД-{seq:04d}-{year}-М`. Доступные подстановки: `{seq}`, `{year}`,
`{year_short}`, `{month}`, `{day}`, `{date}`.

Уникальность обеспечивает не случайное число, а порядковый счётчик с
проверкой по локальному реестру: номер увеличивается, пока не найдётся
свободный.

**Правило при дубликате:** если введённый вручную номер уже есть в реестре,
приложение показывает сведения о существующем договоре и запрашивает
подтверждение (`duplicate_number_policy = "confirm"`, по умолчанию). При
значении `"block"` генерация запрещается. Запись в реестр добавляется
**только после** успешного создания файла, поэтому неудачная генерация номер
не занимает.

## Где хранятся данные

| Что | Где |
|-----|-----|
| Настройки | `%LOCALAPPDATA%\ContractGenerator\settings.json` |
| Реестр договоров | `%LOCALAPPDATA%\ContractGenerator\contracts.sqlite3` |
| Журнал (с ротацией) | `%LOCALAPPDATA%\ContractGenerator\logs\contract_generator.log` |
| Готовые договоры | Каталог, выбранный пользователем (по умолчанию `Документы\ContractGenerator`) |

Права администратора не требуются. Временный каталог PyInstaller для
постоянных данных не используется.

В реестре хранятся только: номер договора, время создания, наименование
компании, ИНН, имя шаблона, путь к результату и статус.

## Запуск из исходников

Поддерживаемая версия Python — **3.11** (проверено также на 3.14).

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe main.py
```

## Тесты

```bat
.venv\Scripts\python.exe -m pytest
```

Тесты используют только синтетические данные: реальные персональные,
юридические и банковские сведения в репозитории отсутствуют.

## Сборка EXE

```bat
build.bat
```

Скрипт создаёт локальное окружение `.venv`, ставит зависимости **только в
него** (системный Python не затрагивается), прогоняет тесты и собирает
`dist\ContractGenerator.exe`. При любой ошибке возвращается ненулевой код
завершения.

Сборка также выполняется в GitHub Actions
(`.github/workflows/build-windows.yml`) на `windows-latest` с Python 3.11;
EXE публикуется как артефакт запуска. Публичные релизы автоматически **не**
создаются.

## Известные ограничения

* Формат `.xls` и старый `.doc` не поддерживаются.
* Аббревиатуры ОПФ (ООО, АО, …) не склоняются — падежные плейсхолдеры для
  них возвращают исходное значение.
* Склоняются только должности из встроенного справочника; остальные
  сохраняются как есть (по замыслу — чтобы не искажать текст договора).
* Пол определяется по отчеству; для ФИО без отчества или иностранных имён
  требуется указать пол в карточке.
* Если плейсхолдер разбит Word на несколько фрагментов, подставленное
  значение целиком наследует форматирование **первого** фрагмента.
* Плейсхолдер не может пересекать границу абзаца.
* Значения, переносимые из шаблонов, не проходят проверку орфографии.
* Реестр договоров локальный: на другом компьютере проверка дубликатов
  номеров работать не будет.
* Приложение не подписано цифровой подписью — SmartScreen может показать
  предупреждение при первом запуске.
